# Gulfood 2026 AI Event Assistant

## Overview
The Gulfood 2026 AI Event Assistant is a web application designed to enrich the experience for visitors, exhibitors, and event organizers at the Gulfood 2026 trade show. It provides AI-powered company analysis, intelligent exhibitor matching, meeting scheduling, and real-time event analytics. The platform offers immediate, free access without registration to maximize engagement, featuring an AI chatbot named "Faris." It supports three user groups—Visitors, Exhibitors, and Event Organizers—with role-based access to specialized functionalities like the Analytics Dashboard. The project aims to improve event navigation, facilitate business connections, and provide valuable insights for all participants.

## User Preferences
Preferred communication style: Simple, everyday language.

## System Architecture

### Frontend Architecture
The frontend is a React 18 application with TypeScript, utilizing Wouter for routing and TanStack Query for state management. UI components are built with Radix UI and shadcn/ui, styled using Tailwind CSS, following a design system inspired by Gulfood.com and GITEX.com with responsive layouts and a custom color scheme. The AI Chatbot, "Faris," offers multilingual support (English, Arabic, Simplified Chinese, Hindi) and role-based assistance (Visitor, Exhibitor, Organizer), including features like visitor registration CTAs, social sharing, and lead capture. The system generates professional, branded PDF reports for analytics and visitor journeys. Key features include an AI response accuracy feedback system, a "Plan my Journey" feature with intelligent, distance-aware itinerary planning, and optimized performance through lazy loading and efficient API calls. Authentication and context management are handled via `AuthContext`, `RoleContext`, and `ChatbotContext`. Dedicated pages exist for `/organizer/login`, `/organizer/admin`, and `/exhibitor/verify`. The chatbot features a tabbed interface ("Chat" and "Right Now") displaying live announcements and upcoming sessions dynamically based on user role and target audience.

**Lead Capture Persistence** (November 2025): The lead capture popup now persists user submission status across page reloads and browser sessions. SessionManager stores sessionId in localStorage (previously sessionStorage) ensuring the same identifier survives indefinitely. On chatbot mount, the system checks `/api/leads/session/:sessionId` endpoint to determine if the user has already submitted their contact information. If a lead exists, the "Stay Connected with Gulfood 2026" popup is suppressed, preventing duplicate captures and improving user experience for returning visitors.

**AI Response Feedback System** (November 2025): All bot responses now feature thumbs up/down feedback buttons enabling users to rate answer accuracy. Feedback is immediately logged to the `chat_feedback` database table with sessionId, messageIndex, isAccurate (boolean), and timestamp. The system prevents duplicate ratings per message and displays confirmation upon submission. This feedback data serves as a critical analytics source for measuring AI performance, identifying problematic responses, and tracking user satisfaction trends over time.

### Backend Architecture
The backend is built with Node.js and Express.js, using a PostgreSQL database (Neon serverless) managed with Drizzle ORM. It provides RESTful APIs for exhibitors, company analysis, meetings, chatbot interactions, leads, referrals, chat feedback, and analytics. It features advanced search capabilities (accent- and punctuation-insensitive), AI integration via OpenAI API for company analysis and chatbot functionality, and a venue navigation system integrating Google Routes API. The backend supports comprehensive referral tracking, lead management with status updates, dynamic PDF report generation, and AI response feedback collection. Authentication is JWT-based, with `requireOrganizerAuth` middleware protecting administrative routes and bcryptjs for secure password hashing. New database tables manage organizers, announcements, sessions, exhibitor access codes, and chat feedback. Protected API routes handle organizer registration/login, and CRUD operations for announcements, sessions, and exhibitor access codes, while exhibitor code verification is publicly accessible. Lead persistence endpoints (`GET /api/leads/session/:sessionId`) enable checking existing lead submissions by session identifier. Chat feedback endpoints (`POST /api/chat/feedback`, `GET /api/chat/feedback/:sessionId`) log and retrieve user satisfaction ratings for AI responses, providing critical analytics data for measuring chatbot performance and user engagement.

**DEC Venue Integration** (November 2025): The system now accurately distinguishes between Dubai Exhibition Centre (DEC) and Dubai World Trade Centre (DWTC) venues with comprehensive exhibitor coverage. Features include: (1) Web scraper using fetch + Cheerio (`scripts/scrape-dec-exhibitors.ts`) that extracts 1,376 DEC exhibitors from gulfood.com with venue, hall, booth, country, and sector data across all 27 alphabet filters with proper deduplication and validation; (2) Ingestion script (`scripts/ingest-dec-exhibitors.ts`) with fuzzy matching algorithm using exact name, normalized name, and name+country matching strategies (>80% similarity threshold) that successfully updated 650 existing exhibitors and added 726 new exhibitors while preserving data integrity; (3) Database now contains 861 DEC exhibitors and 38 DWTC exhibitors (899 total) - fuzzy matching correctly reclassified 125 previously misassigned DWTC exhibitors to DEC; (4) Enhanced storage interface with venue filtering support via `/api/exhibitors?venue={venue_name}` endpoint verified working correctly; (5) Journey planning and itinerary responses now include `venue` and `hall` fields for all matched exhibitors, enabling accurate location-based recommendations and route planning. The scraper uses fetch + Cheerio instead of Playwright due to system dependency constraints in the Replit environment.

**Intelligent Scoring System**: The AI-powered journey planning system (November 2025) uses sophisticated scoring algorithms with robust error handling. Key features include: (1) Brace-aware JSON extraction using character-by-character stack parsing to handle nested arrays/objects correctly; (2) Batch processing of exhibitor scoring (max 10 per batch) to prevent API token truncation; (3) Fail-fast error handling that surfaces truncation/validation failures instead of silent data loss; (4) Pre-filtering of exhibitors by interest categories (40 matching + 10 variety) before AI scoring to ensure sector alignment; (5) Strengthened AI prompts emphasizing interest category matching as the #1 priority with explicit scoring bands (70-95% for matches, 20-50% for non-matches); (6) finish_reason checking to detect and log truncated AI responses. These improvements ensure users receive realistic relevance scores (70-95%) instead of fallback values (50%), and exhibitor recommendations accurately match their selected interest categories.

**Enhanced Exhibitor Assessment Pipeline** (November 2025): The exhibitor assessment system now features a 3-phase validation pipeline with internet research and quality assurance. Components include: (1) **Company Research Service** (`server/companyResearch.ts`) that conducts web searches to gather real-world company intelligence (industry, products, news, company size, business model, target markets, sustainability initiatives) with 7-day caching via `company_research_cache` table using sessionId+companyName+websiteUrl+goalsHash+country composite key; (2) **Assessment Evaluator Service** (`server/assessmentEvaluator.ts`) implementing 7 validation criteria (data accuracy, fairness, goal alignment, geographic relevance, strategic relevance, completeness, consistency) that scores assessments 0-100 and provides detailed feedback with **Dynamic Validation Thresholds** that adapt to research data availability: high confidence (≥70%) requires 85% validation score with comprehensive MENA analysis, medium confidence (40-69%) requires 75% with focus on accuracy of available data, and low confidence (<40%) requires 70% accepting honest assessments with limited information—this prevents unfair penalization for missing details that don't exist while maintaining quality standards when data is available; (3) **Multi-Iteration Validation Loop** allowing up to 2 refinement iterations with retry logic, logging all attempts in `assessment_evaluation_logs` table; (4) **Enhanced Database Schema** with `validationIterations`, `validationScore`, `evaluatorFeedback`, `isValidated`, `researchConfidence`, and `researchSummary` metadata fields in `exhibitor_assessments` table; (5) **Frontend Enhancements** including mandatory website URL input, multi-select primary goals (6 checkbox options), 3-phase progress indicators (research → assessment → validation), and comprehensive validation quality display card showing iteration count, validation score, research confidence, and evaluator feedback. The system ensures high-quality, data-driven assessments by grounding AI analysis in real company research and applying adaptive quality validation that calibrates expectations to data availability.

### Development Infrastructure
The development workflow utilizes tsx for development and Vite (frontend) and esbuild (backend) for production builds. Drizzle Kit manages database migrations, and type safety is enforced using shared schema definitions with Drizzle Zod.
